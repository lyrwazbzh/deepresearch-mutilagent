# 深度研究大纲审批工作区修复设计

## 背景与根因

当前待审批大纲和聊天记录被水平放入仅占页面 35% 的左栏，两个复杂内容区同时被压缩，产生文字竖排、表单过窄和水平滚动。审批请求返回 404 的直接原因是检查点未成功持久化：状态中的 `asyncio.Queue` 被原样交给 JSONB 字段，导致数据库插入失败。

## 已选方案

采用右侧宽工作区审批：

- 待审批时，左侧 35% 区域仅显示用户问题和聊天上下文。
- 右侧 65% 区域临时从研究结果切换为大纲审批工作区。
- 用户确认大纲后，审批工作区消失，右侧恢复研究过程和结果。
- 审批界面使用中文文案，章节和研究问题使用宽表单布局，排序、删除与主操作保持明确的层级。
- 小屏幕下改为上下堆叠，避免任何水平压缩。

## 后端修复

检查点持久化前对状态做递归清理：

- 保留 JSON 原生类型、日期、UUID 和可递归的列表/字典。
- 丢弃以下划线开头的运行时内部字段，包括 `_message_queue`。
- 不再使用 `json.dumps(..., default=str)` 验证后保留原对象的方式。
- 保存前对清理结果执行真实 JSON 序列化验证。

当检查点保存失败时，研究流不应继续向前端声称可以审批；应返回可理解的错误事件。

## 前端布局与交互

- `pendingOutline` 存在时，`ComPageLayout.right` 渲染 `OutlineApprovalPanel`，否则渲染原有 `ResearchDetail`。
- 聊天主区不再渲染第二个并排的大纲面板。
- 大纲面板拆分为固定标题/说明、可滚动编辑区和底部确认操作区，确保主按钮始终可达。
- 错误文案说明“发生了什么”和“用户可以怎么做”，不直接显示会话 UUID。
- 保留现有草稿恢复、版本冲突、防重复提交和 3–12 章限制。

## 验证

- 后端回归测试复现含 `asyncio.Queue` 的状态，先证明保存失败，再验证清理后检查点能持久化。
- 前端集成测试验证待审批面板传入右侧工作区，聊天主区不再包含该面板。
- 组件测试验证中文操作、表单编辑、排序、删除、验证和单次提交。
- 生产构建、后端快速测试和 Playwright 宽屏/窄屏截图验证全部通过后重启本地服务。
